## 🧠 项目优化应该考虑的完整维度

### 一、🎯 受众定位 — 你为谁而建？

这是最核心的问题，因为它决定了后面所有决策。从你的项目可以判断出你至少有 **3 类潜在读者**：

| 受众 | 他们来干嘛 | 他们在意什么 |
|------|-----------|------------|
| **① 同专业同学 / 初学者** | 找笔记抄、跟着学 | 内容能不能直接用、代码能不能跑 |
| **② 招聘方 / HR / 面试官** | 看你的能力和作品 | 项目是否有深度、表达是否专业 |
| **③ 你自己** | 复习、积累、记录成长 | 方便检索、持续维护不累 |

**你现在的问题**：这三类受众的需求是有冲突的。

- 对同学：需要**教程式**的写法（step by step、截图多）
- 对招聘方：需要**作品集式**的包装（结论先行、突出亮点、量化成果）
- 对自己：需要**笔记式**的简洁（关键词 + 代码片段就够了）

> **建议**：想清楚优先服务谁。如果你 2027 年毕业找工作，**现阶段最有杠杆率的定位是「个人作品集 + 技术博客」**，而不只是课堂笔记。

### 二、📐 信息架构 — 内容怎么组织？

你目前的 `nav` 结构有几个问题：

**问题 1：命名不统一**
```
- infrastructure_by_AI    ← 英文，含义模糊
- 一、动手学数据分析       ← 中文带序号
- MySQL_ITcase            ← 英文缩写
- myself_tools            ← 英文
- AI_use                  ← 英文
```
读者看到 `infrastructure_by_AI` 完全不知道是什么。命名应该从**读者视角**出发，而不是从你的文件夹组织方式出发。

**问题 2：AI 生成内容（infrastructure_by_AI）和自己写的内容混在一起**
读者无法判断哪些是你的原创笔记，哪些是 AI 辅助生成的骨架内容。这在招聘场景下是个减分项 — 面试官会怀疑所有内容都是 AI 写的。

**问题 3：Projects 分类逻辑不清**
```
- AI_infrastructure  → project1, project2 （通用名，看不出内容）
- myself_tools       → Git脚本、PPT转PDF
- AI_use             → 功能测试页、Thoughts On AI
- MCM美赛资料
```
这个分类是按**内容来源**分的（AI生成的 vs 自己做的），但读者关心的是按**项目类型/领域**分的。

### 四、🎨 视觉与体验 — 长什么样？用起来怎么样？

你已经做了很多视觉工作（Hero、卡片、时间线、翻转卡片、暗色模式），**视觉层面在个人站里已经中上水平**。但有几个体验层面的问题：

| 问题 | 具体表现 |

| **首屏信息密度过高** | Hero → 关于我 → 学习路径 → 学习资料 → 项目展示 → 工具 → 更新日志，7 个板块堆在一页 |

### 六、🔧 可维护性 — 你能坚持更新吗？

这是最容易被忽略、但最致命的问题。

| 问题 | 分析 |
|------|------|
| **CSS 1096 行在单文件里** | 以后越改越怕出 bug，建议拆分成模块 |
| **JS 487 行在单文件里** | 同上 |
| **内容和样式耦合** | index.md 里大量 HTML div，维护成本高 |
| **没有 CI/CD 自动检查** | 死链、图片缺失、构建失败不会被发现 |
| **`git-revision-date` 插件被注释了** | 意味着读者看不到文章的最后更新时间 |

### 七、🏗️ 技术债与架构合理性

| 项 | 现状 | 风险 |
|----|------|------|
| **site/ 目录进了 Git** | site 是构建产物，不应该在仓库里 | 增大仓库体积，合并冲突 |
| **Data_and_original_files/ 放在项目根目录** | 数据文件和网站源码混在一起 | 不清晰，而且 `.ipynb` 文件很大 |
| **requirements.txt 只有 3 个包** | 没有锁版本（`>=` 而不是 `==`） | 未来构建可能因依赖升级而挂掉 |
| **inline style 散落在 index.md** | `style="border-radius: 20px; font-size: 0.85rem;"` | 维护困难，应该用 CSS class |

## 📊 优化优先级矩阵

综合以上 7 个维度，按 **影响力 × 实施难度** 排序：

```
影响力 ↑
  │
  │  ① 内容更新与项目包装     ★★★★★（影响最大，但需要时间）
  │  ② 信息架构重组/命名规范   ★★★★☆（一次性工作，回报高）
  │  ③ 首页布局精简            ★★★★☆（改动不大，体验提升明显）
  │  ④ SEO + og:image          ★★★☆☆（技术简单，长期受益）
  │  ⑤ 视觉微调（色彩/动效）   ★★★☆☆（锦上添花）
  │  ⑥ CSS/JS 模块化拆分       ★★☆☆☆（维护性好，但读者感知不到）
  │  ⑦ site/ 目录清理 + .gitignore ★★☆☆☆（技术卫生，5分钟搞定）
  │
  └──────────────────────────────────→ 实施容易程度
```
